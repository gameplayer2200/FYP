# 工厂 · 时空强制切换（Level Design）

> 面向实现者。本文的坐标全部相对**各自楼层根节点**（Day / Night），不是世界绝对坐标。
> 最后核对：2026-11-08，基于 `Assets/Scenes/Factory.unity` 实测。
> 术语遵守 `GLOSSARY.md`。改动的技术前提见文末「实现现状」。

---

## 1. 关卡名称与主题

**工厂 · 交接**（Factory: The Handover）

八小时工作制的残骸里，两个班次在同一个空间里叠着。你不是在"参观昼夜"，你是被排班钟安排的那个人——时间到了，不管你走到哪，交接就把你拽过去。

**主题句**：*你控制不了什么时候上班，只能决定上班时做什么。*

**参考**：《泰坦陨落 2》"因果"关的空间切换；但**关键差异**是控制权归谁——那边是玩家的战术工具，这边是时钟的强制安排。这决定了下面所有的设计取舍。

## 4. 核心设计：把"被打断"变成"被安排"

### 4.1 问题

强制切换最糟的形态是：玩家正专注做一件事，突然被搬走，之前的努力白费。这会产生**挫败**而非**压力**。

### 4.2 解法：三段式窗口

90 秒不是"一个任务的时间"，而是**一个班次的时间**。把它切成三段：

| 阶段 | 时长 | 玩家心理 | 设计手段 |
|---|---|---|---|
| **交接后（0–15s）** | 15s | "我在哪？" | 新班次独有的视觉锚点（灯/雾/声音）立刻可见 |
| **稳定期（15–70s）** | 55s | "干活" | 本班次可做的事集中在这个窗口 |
| **预警期（70–90s）** | 20s | "要换了" | 挂钟指针走最后一圈 + 钟声 + 屏幕边缘轻微色偏 |

**关键**：预警 20 秒不是"提示"，是**规划时间**。玩家在这 20 秒里要做完的决策是「我这半件事是现在冲完，还是搬到另一边接着做」。

### 4.3 让它成为"机会"的三个机制

**(a) 跨层接力（主机制）**

排班表要求按序启动 3 台机器（Day 2 台 + Night 1 台）。**天然跨层**——这正是现有设计的价值，强制切换让"必然跨层"从缺点变成节奏。

- 在 Day 启动了 1 号风机 → 被切到 Night → 启动深区送料机 → 被切回 Day → 启动 2 号风机
- **玩家不需要等换班**：换班帮他完成"必须去另一层"这件事

**(b) 食尸鬼作为"班次边界"**

食尸鬼只在 Day 层。它追你时，**钟声一响就是救命的**——你会主动希望换班快到。这让"强制"在某些时刻变成"期待"。

- Day 被追 → 看钟 → 还有 8 秒 → 绕着机器跑 → 钟响 → 脱险
- 这是整个关卡最强的情绪高点，**不要削弱它**

**(c) 不可兼得（待实现，见 §7）**

一个白天要按住、夜里才生效的开关。单人无法同时完成 → 逼玩家算"窗口边界"。

### 4.4 反面做法（明确不要）

- ❌ 不要做"切换瞬间闪白"——廉价，且伤害已证明不必要的视觉过渡
- ❌ 不要在切换时清空玩家手上的进度
- ❌ 不要让食尸鬼跟着切到 Night——那会抹掉昼夜的恐怖差异

## 5. 遭遇设计

### 5.1 食尸鬼（Day only）

| 项 | 值 | 说明 |
|---|---|---|
| 数量 | 2 只（rel (−5,70) 和 (0,0)） | 现有 |
| 巡逻 | 整图漫游 | `roamWholeScene=true` |
| 关键行为 | 换班时留在 Day 层 | 不跟玩家穿层 |
| 设计意图 | **制造"希望快点换班"的情绪** | 见 §4.3(b) |

**建议调整**：2 只都在主厅中段可能太挤。建议把 (0,0) 那只移到深区方向（z≈−20），形成"从深区回主厅时撞见"的节奏。

### 5.2 巡检灯束（Night only）

- rel ≈ (0, 0)，扫过 annex 走廊
- 扫中玩家 → HUD 乱码一瞬 + 刺点，**无伤害**
- **设计意图**：Night 的恐怖来源是"被看见"而非"被伤害"，与 Day 的食尸鬼形成对比

### 5.3 压力曲线

```
强度
 高 │        ╱╲              ╱╲
    │   ╱╲  ╱  ╲    ╱╲     ╱  ╲
 中 │  ╱  ╲╱    ╲  ╱  ╲   ╱    ╲
    │ ╱          ╲╱    ╲ ╱      ╲
 低 │╱                   ╲        ╲
    └────────────────────────────────→ 时间
     出生  首次换班  解谜  锁定  撤离
```

- **出生~首次换班**：低。让玩家熟悉"会换"
- **首次换班**：第一次冲击，必须有明确信号
- **解谜期**：锯齿状，每次换班一个峰
- **锁定后**：平缓。奖励期的松弛
- **撤离**：再起一个峰

| 时机 | 内容 | 载体 |
|---|---|---|
| 进厂 | 值班日志播报当班规则 | `DutyBriefing`（已适配 Factory） |
| 首次换班 | 钟声 + "换班了——夜班开始" | `ShiftClock`（已实现） |
| 首次发现被追 | "有东西看见你了" | `EnemyGhoul.spottedHint` |
| 换班躲过追击 | **无提示**——让玩家自己意识到 | 留白 |
| 解谜完成 | 排班表变锁定器 | `ShiftScheduleBoard` |
| 锁定 | "排班钟停了——锁定白班" | 已实现 |

**叙事原则**：不解释规则，只呈现后果。玩家应该通过"差点被追到，钟响了，得救了"自己推导出时钟的价值。

## 7. 待实现的空间改造

以下是**建议加入**的内容，按性价比排序。

### 7.1 不可兼得的开关（P1，价值最高）

**问题**：现在 Day 和 Night 各做各的，缺少"必须同时"的压力点。

**方案**：在主厅 z≈35 加一个**必须按住**的液压阀（Day 层），它控制 Night 层的泵房排气。按住的瞬间切班 → 手松了 → 失败。

**实现**：复用 `BreakerSwitch` 的按住逻辑，跨层状态经 `FactoryShift` 静态桥。

**坐标建议**：Day rel `(0, -1.5, 35)`；对应的 Night 表现件 rel `(0, -3.9, 35)`。

### 7.2 深区门的位置冲突（P1，修 bug 级）

**现状**：Day 的 `ShiftGate` 在 rel `(5.5, -24.2)`，Night 的在 `(6.1, -11.2)`。**两者 XZ 不对应**（z 差 13 米）。

**后果**：玩家从 Day 的闸门位置被切到 Night 时，会落在**闸门后方**——可能卡在门里或门外错误的一侧。

**修法**：把 Night 的 ShiftGate 移到 rel `(5.5, -24.2)` 附近，或调整 Day 侧的。**需要你确认哪个位置是对的。**

### 7.3 `[时空差异]` 节点（已落地，2026-11-10）

**已实现的是"单向封锁"：同一片 XZ，白天被柜子堵死、夜里是空地（或反过来）。**
这是玩家能自己看出来、且不需要任何文字的昼夜差异——走过去撞墙，换班再走，通了。

用的是场景里现成的 `MetalCabinet01_1/2`（CC0 工厂道具，0.73×1.73×0.63/1.03 m，
带实体碰撞），不是自制多边形。7 台堵白天、6 台堵夜里，全部挂在各层 `[时空差异]` 下。

| 层 | 位置（世界 XZ） | 台数 | 效果 |
|---|---|---|---|
| Day | z≈34，x −2.85…4.25 | 7 | 主厅两处窄口（x[−3,−1.5]、x[2,4.5]）**整排封死** |
| Night | z≈60，x −5.6…−0.55 | 6 | 夜侧对应走廊封死，**同一段白天是通的** |

实测通行矩阵（`Physics.CheckCapsule`，胶囊 r=0.3）：

```
Day  z=34 : # # # # # # # # # # # #   ← 全堵
Night z=34: # # # # # # . . . . # #   ← 两个缺口
Day  z=60 : . # . . # # # # . . . .   ← x 0.5…3 通
Night z=60: . # . # # # # # # # . .   ← x −6…0 全堵
```

Night 层比 Day 层多堵 8 格、Day 层比 Night 层多堵 5 格——**两边各有对方没有的路**，
所以换班不是"换个滤镜"，而是真的换了一套可走的空间。

原 §7.3 那张"5 件测试物"的表（深区封锁闸 / 主厅货箱 / 泵房矮墙 / 主厅横梁）**已作废**：
那些位置是包围盒推算的占位假设，本轮全部按实测通行矩阵重做。

**摆位注意**：柜子必须贴到地板（`position += up * ((floorY + 0.005) - bounds.min.y)`），
否则会悬空几十厘米，玩家从底下钻过去。碎石 `Debris01_*` 看着挡路其实只有 7–35 cm 高，
**不能用来封路**（实测胶囊直接跨过去）。

## 8. 失败与救援

| 情况 | 处理 | 已实现？ |
|---|---|---|
| 落点被几何挤住 | **只许往上抬**（站上柜顶/机器顶），不横向挪 | ✅ `SettleOnLayer()` |
| 实在找不到落点 | **宁可不切**，警告日志 | ✅ |
| 玩家空中/充电中/门洞里 | 最多延后 1.5 秒 | ✅ |
| 切换后立刻又要切 | 1 秒冷却 | ✅ |
| 被困在夜侧回不来 | **靠下一次换班**（90 秒） | ⚠️ 见下 |

**最后一条是真实风险**：Night 侧只有去 Waterfront 的门，**回 Day 只能等换班**。90 秒对一个想离开的玩家是可接受的，但建议：
- 在 Night 的归途门附近加一个**手动请求交接**的按钮（冷却 30 秒），给玩家一点掌控感
- 或者把夜侧归途门做成双层门（昼夜各一扇，物理位置重合）

## 9. 可见性结论（实验证明，勿重复踩坑）

**测试方法**：同一相机在 Night 层内部渲染，分别只开 Night 层 / 两层全开，比对 PNG 字节。

```
站在 Night：only=380508B  both=380507B   → 差 1 字节（浮点噪声）
站在 Day：  only=418506B  both=418508B   → 差 2 字节
```

**结论：两层几何天然隔离，看不见彼此。**

之前误判过一次「抬头能看见 Night 地板」，实际是 **Day 自己的屋顶**（`Factory1RoofBase01`，高出视线 6.6m）。**不要为"穿帮"做视觉过渡，问题不存在。**

`FactoryTimeSwap.ApplyViewMask()` 仍然保留，但它是**可选优化**（省 493 个 renderer），不是必需品。
