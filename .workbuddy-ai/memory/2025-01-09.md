## 方案 B：自动配对（挪门后零操作）

### 已完成
1. **PortalWindow 新增 `autoPair` 模式**：
   - `autoPair = true`（默认）时，配对信息完全由门名运行时推导，不再需要 WorldLink 资产。
   - 取景参数（rtHeight、farClip、nearClip、preloadRadius、mirrorU、openingPath）优先从 Link 读取，Link 为空时用 PortalWindow 上的字段兜底。

2. **自动推导规则（命名约定已改为 `-A` 后缀）**：
   - **配对门名**：`anywhere-door-X-A` ↔ `anywhere-door-X`
   - **目标场景**：`-A` 型（世界侧）→ `X`（`-` 替换为 `_`）；非 `-A` 型（实验室侧）→ `SpecimenLab`
   - **朝向差（mapYaw180）**：目标世界加载后，运行时比较两扇门 Y 轴朝向，差 > 90° 时自动设为 true

3. **兼容旧配置**：
   - 如果 `autoPair = false`，完全回退到旧行为（必须指定 WorldLink）。
   - 即使 `autoPair = true` 且 Link 存在，取景参数仍优先从 Link 读取（保护已有调参）。

### 结果
- 挪门到别的场景 → 门名不变 → 配对自动正确 → **零操作**
- 改门朝向 → mapYaw180 运行时重算 → **零操作**
- 新增门 → 按命名约定起名 → 自动配对 → **零操作**

### 验证建议
1. 在 Inspector 中把一扇门的 Link 字段清空，确认 autoPair 已勾选。
2. 进入 Play 模式，验证该门仍能正常取景和穿行。
3. 在 Scene 视图中旋转一扇门，验证 mapYaw180 自动更新（可通过 Debug OSD 查看）。

## DoorLinkAutoRepair 修复：玩家消除问题

### 问题
运行 **FYP/门配对/扫描并自动重配** 时，扫描和写回阶段使用 `OpenSceneMode.Single` 打开每个场景，导致当前场景（含玩家）被关闭，玩家对象被销毁。

### 修复
`DoorLinkAutoRepair.cs`：
- 扫描阶段：`Single` → `Additive`，扫描完关闭非原始场景
- 写回阶段：`Single` → `Additive`，写回完关闭非原始场景
- `finally` 恢复原始场景的 `Single` 保持不变（收尾用）
