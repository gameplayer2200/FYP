## 世界按需加载（流送）现状核查

用户问"靠近传送门才加载对应世界，避免加载过多卡顿，请给解决方法"。
核查结论：**该功能已实现**，位于 `Assets/Scripts/World/WorldStreamer.cs`（静态类，FYP.World 程序集）。

### 架构分工
- `WorldLink`：只描述"谁通往谁"（worldSceneName / worldDoorName / openingPath / preloadRadius 等）
- `PortalWindow`：只负责取景 + 穿行；OnEnable 调 `WorldStreamer.Register(this)`，Update 调 `WorldStreamer.Tick()`
- `WorldStreamer`：场景装卸的唯一裁决者

### 三条规则（代码实测确认）
1. **需求装载**：玩家进入某门 `preloadRadius` → 装载该门目标世界
2. **远离卸载**：某世界关联的所有门都超出 `2×preloadRadius + ReleaseMargin(2m)` → 卸下
3. **总量封顶**：`MaxLoadedWorlds = 3`（含实验室）。满了先淘汰"需求最弱"（离玩家相对最远）的可卸世界；
   腾不出空位就暂缓装载

### 永不卸载的保护
- 实验室（玩家根对象所在场景 = homeWorld）
- 玩家当前所在世界（`NotifyCrossed` 穿门时登记 currentWorld）
- 任何"门还开着"的世界（pinned）

### Play 模式实测（2026-10-18）
- 开局：`存活=SpecimenLab (共1个)`；玩家出生点 (1.87,0.27,2.83) 距 Metro 门 (3.8,0,5.1) ≈3m < 6 → Metro 自动装载
- 装载完成：`存活=SpecimenLab,Metro (共2个)`
- 玩家移到 (0,0.27,60)（远离所有门）→ Metro 自动卸载，回到 `存活=SpecimenLab (共1个)`
- 结论：**按距离装卸 + 上限封顶均正常工作**

## 已实施：方案 A —— 延迟激活（2026-10-18）

用户确认：FactoryNight / Flooded-Grounds 两扇实验室侧门**不需要了**；先做方案 A。

### 改动（仅 `Assets/Scripts/World/WorldStreamer.cs`，+151/−6）
装载拆成两步：
1. **预载**：进入 `preloadRadius` → `LoadSceneAsync` + `allowSceneActivation = false`，
   progress 走到 0.9 停住（此时 `scene.isLoaded` 仍为 **false**、根对象 0 个）
2. **激活**：进入 `preloadRadius × ActivationRadiusFactor`（默认 **0.55**）、或门开着、
   或玩家就在该世界 → `allowSceneActivation = true`

新增字段/集合：
- `ActivationRadiusFactor`（public static float，默认 0.55）
- `preloaded`（HashSet，预载完成待激活）
- `preloadOps`（Dictionary<string, AsyncOperation>，激活时要拿它置 allowSceneActivation）

### 两个必须记住的坑（都已修）
1. **`allowSceneActivation = false` 时 `op.completed` 永不触发** —— 不能靠它清 pending，
   必须每帧轮询 `op.progress >= 0.9`。
2. **激活到 `isLoaded` 之间有一帧空窗** —— 此时世界既不在 pending 也不在 preloaded 的保护里，
   装载循环会误判"还没加载"并再次 `BeginLoad` → **同一场景被加载两遍**（实测场景列表出现两个 Metro）。
   修法：`Activate()` 后**故意不从 `preloaded` 移除**，等 `IsLoadedNow` 为真再摘
   （见 `TickPreloadAndActivation` 第 0 步）；同时装载循环的保护条件必须含 `preloaded`。

### Play 模式实测（FactoryDay 门，preload 4.5 / 激活 2.48）
| 玩家距门 | 结果 |
|---|---|
| 4.01m | `待激活=1`，FactoryDay `isLoaded=False`、根对象 0 ✓ 只预载 |
| 2.02m | FactoryDay `isLoaded=True`、根对象 7 ✓ 已激活 |
| 40m 外 | Metro + FactoryDay 全部卸载，`存活=SpecimenLab (共1个)` ✓ |

场景列表全程无重复项。

### 注意
- `ActivationRadiusFactor` 是静态字段，**不在 Inspector 里**，要调得改代码。
  若需按门单独调，可考虑把它下放到 `WorldLink`（需改 WorldLink + 8 条资产）。
- 未激活时 `IsWorldReady` 为 false → `PortalWindow` 不建取景，门洞暂时是暗板。
  这是延迟激活的预期代价。

## 死亡重生起身动画（2026-10-18）

### 问题
控制器里 **`Dead` 状态是死胡同**——没有任何出口转移，`BatterySystem.Restart()` 也不碰动画，
所以瘫倒后角色永远保持倒地姿势。

### 用哪段动画
`UAL2_LayToIdle`（1.533s）。验证方法：读 clip 的 `RootT.y` 曲线首尾值——
- `UAL1_Death01`：0.947 → 0.125（站着→躺下）
- `UAL2_LayToIdle`：0.079 → 0.946（躺下→站起）

首尾高度正好接上，是死亡动画的逆过程。

### 实现
- **控制器**（15 参数 / 21 状态）：新增 `GetUp` trigger + `GetUpDone` bool；
  `GetUp` 状态 motion=`UAL2_LayToIdle`；`Dead → GetUp`（If GetUp）；
  `GetUp → Idle`（**If GetUpDone**，不用 hasExitTime）
- **PlayerAnimatorProxy**：`PlayGetUp()`（先复位 GetUpDone 再发 trigger）、`SetGetUpDone(bool)`
- **BatterySystem**：`IsRecovering` 属性 + `recoverUntil` 时间戳；`Restart()` 里 `PlayGetUp()`
  并置计时；`Update()` 到点调 `EndRecover()`（置 GetUpDone + 解锁移动）
- **PlayerMovement**：`recovering` 期间锁移动/跳跃/翻滚/蹲伏

### 两个踩过的坑（重要）
1. **`GetUp → Idle` 不能用 hasExitTime**：实测该转移在进入的同一帧就判定完成
   （状态 normalizedTime 残留旧值 9.24，没复位），起身动画被整个跳过、直接回 Idle。
   改成 bool 条件 `GetUpDone` + 代码计时，确定可靠。
2. **`Invoke(nameof(EndRecover), getUpDuration)` 延时不可靠**，改成 `Update` 里比较
   `Time.time >= recoverUntil`。日志实测 `t=7.28 until=7.27`，计时本身是准的。

### 排查方法备忘
- 编辑脚本会触发域重载，**静态单例（`BatterySystem.Instance`）会被清空**，
  此时要 `FindObjectOfType` 拿实例，或退出重进 Play。
- 控制器改了状态/转移后，**必须重新进 Play** 才生效；运行中的 animator 是旧快照。
  判据：`anim.Play("GetUp")` 无效 = 运行时没有该状态。

### 验证
`IsRecovering=True`、`clip=UAL2_LayToIdle`、`inGetUp=True`、`length=1.53` ✔

## FactoryDay 改为启动即加载（2026-10-18）

### 需求
靠近 FactoryDay 的任意门会卡一下（世界装载+激活）。用户要求挪到游戏启动时完成。

### 实现（3 处）
1. **`LabToFactoryDay.preloadRadius`: 4.5 → 0**。
   代码约定「半径 ≤0 = 开局即加载」，且 `WorldStreamer` 的需求判定里
   `nearestRadius <= 0f` 恒为 true → 该世界**永久有需求 = 常驻**。
2. **`PortalWindow`**：渲染门控 `renderRadius = PreloadRadius × 2`，半径 0 会乘出 0
   → **门洞永远不渲染**。新增常量 `ResidentRenderRadius = 30f` 兜底：
   `PreloadRadius > 0 ? ×2 : 30`。
3. **`WorldStreamer`** 卸载循环：加 `if (wanted.Contains(name)) continue;`。
   否则半径 0 的保活范围只有 `0×2 + 2 = 2m`，玩家一走开就会被误卸。这条才让它真正常驻。

### 实测
- 启动后：`存活=SpecimenLab,Metro,FactoryDay (共3个)`，`FactoryDay-Lab` 取景 `ready=True` ✔
- 玩家移到 50m 外：FactoryDay **仍在**，Metro 正常卸载 → `存活=SpecimenLab,FactoryDay (共2个)` ✔

### 注意
`MaxLoadedWorlds=3`。FactoryDay 常驻后占掉一个槽位，其余世界同时只能再加载 1 个。
若以后新增实验室侧门，需要调大上限或改成按需加载。
