### 2. Shift 前滚翻（新增功能）
- **按键方案**：Shift 双击（0.25s 内两次按下）触发翻滚；**按住仍是冲刺**，两者不冲突。
  （用户原话是"按 shift 翻滚"，但 Shift 已绑定冲刺，双击是标准解法）
- `PlayerAnimatorProxy.cs`：新增 `PlayRoll()`，字段 `roll = Animator.StringToHash("Roll")`。
- 控制器：新增 `Roll` trigger 参数（13 参数）、`Roll` 状态（motion=`UAL1_Roll`，20 状态）；
  进入转移 Idle/Walk/Run/CrouchIdle/CrouchWalk → Roll（Roll trigger + Grounded=true）；
  退出转移 Roll → Idle（hasExitTime，exitTime=0.95）。
- `PlayerMovement.cs`：
  - 新增字段 `rollSpeed=2.5`、`rollDuration=1.4`、`rollCooldown=0.3`、`doubleTapWindow=0.25`
    与状态变量 `rolling`/`rollDir`/`rollTimer`/`rollCooldownUntil`/`lastShiftTapTime`。
  - `Update()` 里 Shift `GetKeyDown` 双击判定 → `TryStartRoll()`；`rolling` 时 `RollTick()`。
  - 移动块改为 `if (rolling) { horizontalVel = rollDir * rollSpeed; } else { ...原逻辑... }`
    ——翻滚期间锁输入、沿触发瞬间锁定的方向匀速推进（动画是原地滚，位移由代码给）。
  - 翻滚中禁止蹲伏切换、禁止跳跃。
  - `TryStartRoll()`：地面 + 非充电 + 非冷却才可；方向取输入方向（无输入则正前方）；
    蹲姿起滚先站起。
- **Play 模式实测**：位移 3.53m（预期 2.5×1.4=3.5m，吻合），动画播 `UAL1_Roll` 后自动回 Idle。

### 关键坑：SerializeField 新字段的"旧默认值"陷阱
给场景里**已存在**的 MonoBehaviour 新增 `[SerializeField]` 字段后，Unity 会立刻把
**当时的默认值**固化到内存中的场景实例。此后**改代码里的默认值不会生效**（运行时仍读到旧值），
而场景文件里又还没有这些字段（`grep` 不到），极具迷惑性。
- 排查：`AddComponent(Type)` 造临时实例读编译期默认值 → 确认程序集是新的；
  再读场景实例 → 值不同 → 锁定是场景实例残留。
- 解决：显式 `SetValue` 写入场景实例 + `EditorUtility.SetDirty` + `SaveScene`，
  之后场景文件里才会出现 `rollSpeed: 2.5` 等字段。
