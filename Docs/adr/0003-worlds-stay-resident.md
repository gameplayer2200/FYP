# 世界常驻，不在穿门后卸载旧世界

提案 §6.1 写的方案是"穿门后卸载旧世界"以控制显存。但当前实现是两个世界同时 Additive 常驻、相距 72m 零重叠，
这正是"穿门零卡顿"能成立的原因——卸载会引入加载尖峰，而尖峰只能靠开门动画那 1–2 秒去遮，遮不住就破坏无缝感。

MVP 阶段我们决定**保持双世界常驻**。依据是量级：两个场景的 YAML 各约 2MB，常驻代价可忽略；而"卸载旧世界"
是为"世界数量多、单世界大"准备的优化，属于完整版阶段的事。

## Consequences

世界数量增长到 4–5 个后必须重新评估——显存与内存随世界数线性增长，且每个世界的灯光/后期会互相叠加。
因此加载职责要收敛到一个可替换的抽象（`WorldStreamer`）之后，"常驻"与"延迟卸载"只是它的两种实现，
将来切换不改调用方。
