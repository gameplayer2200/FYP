# 派单模板（DSH 子代理委派）

> 为什么有这份文件：`level-designer` 被连续委派 **3 次**，3 次都在「数据齐了、准备写文档」的同一位置耗尽上下文，
> **一个字都没写出来**。这不是偶发，是派单方式的系统性问题。本文记录根因与修法。
> 约定基础见 `.dsh/agents/README.md`（那份是框架载荷，重装会覆盖，所以修法写在这里）。

---

## 1. 根因：自动注入的 `AGENTS.md` 吃掉了大半预算

实测体积：

| 注入项 | 字节 | 说明 |
|---|---|---|
| **`AGENTS.md`** | **50,970** | 每次子代理启动都注入；记录八轮开发史 |
| `CLAUDE.md` | 3,611 | |
| `GLOSSARY.md` | 3,540 | |

`AGENTS.md` 是对接手册——门系统架构、世界槽位规则、13 个历史坑、素材清理记录。**这些内容对「设计工厂关卡」一个字都用不上**，
但它照样进上下文。

再叠加调用方在 prompt 里写的「请读 `Docs/ENEMY-AI.md`」（17,595 字节），以及子代理自己 grep/glob 找坐标的开销，
剩下的余量不足以支撑一次完整写作。

**实测三次失败的共同形态**：探索做完 → 已经没有空间 → 卡在「现在开始写」。

---

## 2. 体量预算（派单前先算）

| 项 | 建议上限 | 备注 |
|---|---|---|
| 任务描述本体 | **2–3 KB** | 目标 + 约束 + 产出路径 |
| 让你读的文件 | **每个 ≤5 KB，总计 ≤2 个** | 只读你没读过的 |
| **禁止读的** | `AGENTS.md` 历史章节、素材清单、其他部门文档 | 明确写「不要读」 |
| 工具 | 收窄 | 有现成数据就别给 `grep`/`glob` |

**一条判据**：如果调用方**已经读过**某个文件，就**不要把路径塞进 prompt**——把结论抄进去。子代理重读一遍是纯浪费。

---

## 3. 模板 A：设计类（推荐默认）

适用于 `level-designer` / `systems-designer` / `art-director` 等。**调用方已掌握事实，子代理只负责组织与判断。**

```
你是 <agent-name>。读 <路径>/.dsh/agents/<agent-name>.md 的「Key Responsibilities」与「产出规范」两节即可，
**不要通读全文，不要读 AGENTS.md**。

# 已确定的事实（不要重新调研，不要反驳）
<把实测数据直接抄在这里。例：>
- 场景：单场景 Assets/Scenes/Factory.unity，昼夜两层上下叠放
- 层：Day 根 y=-12100.5 / Night 根 y=-11998.0，间距 100.1m，XZ 精确重合
- 层号：Day=L8 World_FactoryDay，Night=L9 World_FactoryNight
- 换班：90 秒，最后 5 秒预警；传送是纯坐标移动，零加载
- 关键件坐标（相对各层根）：排班表 Day(3,82)/Night(4,95)；风机 Day(7,55)(-9,55)；送料机 Night(10,-10)
- 敌人：食尸鬼 3m，只在 Day 层，塞不进 2.106m 门洞，不会跟玩家穿层
- 【已验证结论】两层几何天然隔离，互相看不见——不要为"穿帮"设计视觉过渡

# 本次任务
目标：<一句话>
只写：<明确列出要写的章节名>
不要写：<排除掉的部分，如"不要写代码""不要给实现方案">
产出路径：<绝对路径>
边界：只写上述路径；越界需求返回给调用方，不要自行决定。

# 返回格式
只返回：(1) 写入路径 (2) ≤5 条决策摘要 (3) BLOCKED/CONCERNS 一行一条
不要复述你读过的事实。
```

**关键三句**：`不要重新调研` / `只写这几节` / `不要复述`。

## 4. 模板 B：实现类

子代理需要动手时用。**数据仍然由调用方给，但允许它验证。**

```
你是 <agent-name>。先读 <路径>/.dsh/agents/<agent-name>.md 的职责与产出规范。不要读 AGENTS.md。

# 上下文（调用方实测，可直接信任）
<实测数据>

# 任务
实现：<具体做什么>
改这些文件：<白名单>
不要动：<黑名单>
验证方式：<可执行的命令或调用>

# 返回格式
(1) 改了哪些文件 (2) 验证结果（贴实际输出，不要转述）(3) 未决问题
```

## 5. 模板 C：审查类

```
你是 <agent-name>。读角色卡的 "What This Agent Must NOT Do" 与产出规范即可。

# 被审对象
路径：<...>
作者声称：<一句话>
请核对它与以下事实是否一致：<事实清单>

# 返回格式
每条发现：位置 / 问题 / 建议修法 / 严重度
不要给总体评分，只列发现。
```

## 6. 反模式（都是实际踩过的）

| 反模式 | 后果 | 改法 |
|---|---|---|
| ❌ 「请读 `Docs/XXX.md`」而你已读过 | 重读一遍，白烧预算 | 把结论抄进 prompt |
| ❌ 不给写作范围，让它「设计整个关卡」 | 范围无边 → 无限探索 | 列出要写的章节 |
| ❌ 依赖它自己 grep 找坐标 | 猜错 + 烧预算 | 调用方先 `execute_code` 实测 |
| ❌ 「请完整通读角色卡」 | 140 行卡片 + 51 KB AGENTS | 只读指定两节 |
| ❌ 让它「先调研再写」 | 三次失败的标准形态 | 调研归调用方，我只负责整理 |

---

## 7. 失败后怎么办

**不要原样重试。** 三次实测证明它会以同样方式再失败。

按顺序：
1. **看有没有落盘**——`ls <产出路径>`。命名的产出物不在磁盘上 = 该阶段失败，不管返回文字多流畅。
2. **判断是不是体量问题**——如果它说「数据齐了，开始写」，那就是体量问题，**减半 prompt 再试**或拆两轮。
3. **调用方自己写**——如果调用方已掌握全部事实，自己写往往比重新派单快。工厂关卡就是这样收尾的。

---

## 8. 一道检查题

派单前问自己：

> **「这个子代理要读的东西，我是不是都已经读过了？」**

若是，就不该把路径给它——把结论给它。
